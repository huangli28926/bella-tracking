埋点落库 + 关键验收

判断由当前对话模型完成（看示意图、搜代码、追参数）。 脚本只做 dump / 渲染 / 建链 / 跑验收。真相源是 impl.json，不要只改 HTML。 公司统一的是 dig-log SDK（$ULOG.send）。项目二次封装（如某仓的 sendLog）不写进 Skill，进仓后探测，跟随落点文件。

Excel → 落库 HTML SDK + 项目封装 Playwright 关键路径 空值自修复 历史埋点关系

详细规则（按需读）

  • 公司 SDK 档案 — 1.3.0 / v3
  • 调用适配 — 二次封装探测与写码规则
  • 关键路径验收规则 — 字段与引擎职责
  • 验收断言规则 — 空值与自修复分类
  • 历史埋点静态扫描 — 路由 / 调用 / 跳转

可读合订：reference/REFERENCE.html。从用户消息取 --excel= 路径。仓库根执行脚本。

硬性禁止

  • 用文档「页面名称」过滤事件或当落点页面
  • 编造 props.xxx / window.xxx（window.__user 除外）
  • 把某个项目的封装名（如 sendLog）写进 Skill 或当成全公司标准
  • 在没有该封装的仓里发明封装；为了统一把旧页 SDK 直调改成封装
  • 改写文档 uicode：只从 Excel → events.json 读取；禁止写入 impl.json、禁止落库页编辑、禁止用现网旧值覆盖。不一致只填 uicodeConflict

定位证据优先级

给埋点找「落在哪段代码」时，按下列顺序取证（先硬后软）。页面名称不可靠，禁止当依据。

  1. 代码里已有这个 evtId — 最硬，直接对账
  2. hint.api — 人工标过接口字段
  3. 提示图 / hint.note — 人工矫正线索
  4. 示意图上的可见文案 — 和 JSX 文案对上
  5. 事件名称 — 文档里的名字，辅助搜
  6. uicode — 只当 SDK payload.uicode（值必须抄 events.json），不当「找文件」依据
  7. 页面名称 — 禁止当依据（Excel 页面名常和真实路由对不上）

A落库文档

先做

  1. dump-excel.js --excel=...（需网络下示意图；同时写出 _raw/adaptor.json）。不要把此时空 HTML 交给用户。
  2. 读 _raw/{文档名}.events.json。click / view 一起按 docIndex 分析，不分两批。
  3. 读 _raw/adaptor.json 与 reference/call-adaptor.md。code 按 adaptor 的 styleId 渲染，不要默认 sendLog。

交付 / 停

交付{文档名}-落库.html + 已填落点/参数的 impl.json。打断时把当前 evt 的服务 URL 发给用户（页面已打开）。

停每条 needsConfirm 在 confirm-event --wait 上停，不要攒到最后再出交互界面。全部分析完后若还有未 confirmed，停在 B 扫尾。未明确说改业务源码前不进入路径 C。

不要等全部事件写完才开服务。写回后立刻重渲 HTML；若该条 needsConfirm，跑 confirm-event.js --evt=... --if-needed --wait。第一次打断拉起 serve-impl，后续只换 URL。全部参数 high 且落点明确的条不打断（medium / low 须人工确认）。

逐条事件

  1. Read _raw/images/{evtId}.png（无图则打开 diagramUrl）。
  2. 有 hint.images 再 Read 提示图；hint.note / hint.api 作线索。
  3. Grep adaptor.sourceRoots 的 evtId。已有调用 → status: existing，对账参数，styleId 跟该文件。
  4. 未命中：用示意图可见文案 + 事件名称搜源码。页面名称只当原文备注。
  5. uicode 原样抄 _raw/{文档名}.events.json 同 evtId 的值写入 SDK payload / snippet。禁止改写、禁止按路由猜。落点路由与文档 uicode 不一致 → 只填 uicodeConflict。
  6. 定 targetFile / functionName / lifecycle（click→onClick；view→useEffect 或 IntersectionObserver）。
  7. styleId：fileStyle[targetFile] > 同目录最常见 > defaultStyleId > sdk-send。用对应 snippet 填 code。
  8. 参数解析顺序：已有 expression（及 valueKind）→ hint.api → hint 图/note + 示意图 → 仓级惯例 → 同文件已有埋点 → 按「用途说明」追变量。抄不到：expression 留空，confidence: low，列入 unresolved。落库页可填 JS 或备注（valueKind: prompt），备注给路径 C 当写码提示词。
  9. 按 evtId 合并写回 _raw/{文档名}.impl.json。不要覆盖 hint / confirmed。
  10. 写回后立刻重渲 HTML。若该条 needsConfirm 且尚未 confirmed：跑 confirm-event.js --excel=... --evt={evtId} --if-needed --wait。用户勾选「已确认」并保存后继续下一条。全部参数 high 且落点明确的条不打断（medium / low 须人工确认）。

needsConfirm：status 为 unresolved/pending、unresolved[] 非空、缺 targetFile、任一参数 expression 为空或 confidence 为 low/medium、有 uicodeConflict。任一命中即打断。medium 不写入 unresolved[]。expression 可填 JS 或自然语言备注。

B人工矫正（扫尾）

只处理 A 未打断、或打断后仍未 confirmed 的条。若已全部确认，B 自动完成。

  1. confirm-event.js --excel=... --evt={第一条未确认} --wait，或 serve-impl.js --excel=... --evt=...（默认 http://127.0.0.1:3920，自动打开浏览器；--no-open 可关掉）。
  2. 让用户在服务里的 HTML 矫正，不要只开本地文件（静态只读）。确认过的事件勾选「已确认」，写入 confirmed。
  3. 保存后以磁盘 impl.json 为准；后续路径只读该 JSON。合并写回不要覆盖 confirmed。

C写业务埋点

前置用户明确确认改业务源码（adaptor.sourceRoots）。

  1. 按矫正后的 impl.json 写调用：用该事件的 styleId / 落点文件已有写法。DOM 声明式须再确认。uicode 必须抄 events.json，禁止沿用现网旧值。valueKind === 'prompt' 时把 expression 当写码提示词，禁止当 JS 粘贴；写出真实表达式后回写 impl.expression。
  2. 写完后由模型根据代码补全 pageKey + accept（trigger / preconditions≈sharedSteps / navigatesAway / dataDeps）。读 reference/accept-chain-rules.md。
  3. 不要让用户填配置文件；不要在 skill 脚本写死业务 locator。
  4. 跑 build-accept-chain.js（可选 --write-impl 仅规范化已有 accept）。检查同页聚类、navigatesAway 拆 path、pending 缺 pageKey/trigger → 模型补 impl.json 后再建链。

交付代码 diff + 更新后的 impl.json.accept。

D关键验收

先做

  1. 确认 impl.json 已有 pageKey + accept.trigger；缺则先补再 build-accept-chain。
  2. --plan-only 把路径给用户看。

交付

  • accept/{文档名}-验收.html（含 fired.action）
  • 真实验收后生成 {文档名}-终稿.html；可用 render-final 重跑
  • plan-only 不生成终稿

确认后跑

  1. run-accept.js（可 --evt= 精点）。
  2. 根目录 .env：baseUrl=origin，seedUrl=完整 path+query（禁止删减）。每条 path 都 goto(seed) 再点到子页。
  3. 先让用户选择 Playwright 设备：--device=mobile（iPhone 13）或 --device=pc（桌面视口）；未选择不启动浏览器。遇登录页先登录，态写入 docs/tracking/.auth/storage.json 复用。
  4. 报告每条两图：accept/shots/{evtId}.png + _raw/images/{evtId}.png。

断言要点

  • 必须发出：evtId + eventType；uicode 以文档为准，有 expect 则必须一致（空上报也 fail）。
  • '-' / 空 / 缺失 → 不判 fail，写入 emptyParams，summary.needConfirm 提醒人工确认。
  • plan-only 的 skip 不算失败。

E空值自修复

触发用户说「自修复 / 修空值 / 诊断空值」，或 needConfirm > 0 且用户要求处理。

  1. diagnose-empty.js → 读 accept/{文档名}-空值修复.json。
  2. 对每条 issues[]：对照 targetFile 真实埋点调用、落库 expression/sourcePath/hint、验收 fired，校正 category（脚本仅为启发式）。
  3. 默认可写：impl.json 的 expression / sourcePath / accept.dataDeps|waitApis。写完按需建链、精点重跑、更新验收与终稿。
  4. 禁止擅自改业务源码：needs_prop_plumb / needs_product_decision 只填方案交用户。
  5. data_genuinely_empty：标注可忽略，不改代码。
  6. 最多 2 轮；仍空则停，剩余标人工项。

F历史埋点关系

触发用户说「梳理历史埋点 / 历史埋点关系 / 扫描已有埋点」。

  1. 仓库根执行 scan-history-tracking.js。不读 .env seedUrl。
  2. 探测 adaptor → 扫路由表 + 封装 / $ULOG.send + history.push。
  3. 写出 docs/historyTracking/YYYY/MMDD_HHmmss.html（另存同名 _raw/*.json）。
  4. 把绝对路径和 file:// URL 发给用户。--open 可用系统浏览器打开。

交付HTML 关系图（页面与埋点 + 页面跳转）。不改业务源码。

SDK / 二次封装

Skill 只认识公司 SDK。验收 hook $ULOG.send。业务写法跟落点文件走。

  1. HTML / ejs 脚本 URL → sdk/lianjia-ulog-1.3.json 或 sdk/lianjia-ulog-v3.json
  2. 谁 export 且转调 $ULOG.send(变量, …) → 二次封装
  3. 写码：targetFile 已有写法 > 同目录 > defaultStyleId > SDK 直调
  4. 禁止在没有封装的仓里发明封装名

可选锁定：docs/tracking/adaptor.json 或 .tracking/adaptor.json（只覆盖 sdkId / defaultStyleId）。

status: existing · located · unresolved · pending confidence: high 不打断；medium / low 或表达式为空须人工确认（medium 不写入 unresolved） accepted 仅 existing 可 true
  • styleId：adaptor.styles[].id。上例 sendLog 来自探测，不是 Skill 内置
  • pageKey + accept：模型按代码填写；build-accept-chain 只聚合/校验。缺 pageKey 或 accept.trigger.kind → pending
  • 禁止在 impl.json 写 uicode 字段；snippet / 业务调用里的 uicode 必须等于 events.json 同 evtId 的值，脚本会强制改回

  • 找不到图/文件/参数：写入 unresolved，继续下一条，不用页面名称兜底
